## WHAT

### 1. `jobs/batch_1000_eval.py` — the 1,000-action session

A deterministic, **SYNTHETIC** operational session: 1,000 proposals at 10 Hz, each evaluated by the
real envelope (`app.envelope.evaluate`), each recorded through the real ledger
(`app.decision_ledger.record_decision`, so every record is contract-validated), and each replayed
down both arms (`app.replay.compare`).

The session is built from **families**, not random noise, because a random walk exercises five rules
by accident and none of them on purpose. `index % 100` selects the family, so the counts are exact
rather than sampled:

| Family | n | What the world is like | Rule that decides |
|---|---:|---|---|
| `nominal` | 450 | nothing wrong | `ALLOW` |
| `obstacle` | 50 | an object sits in the swept corridor | **V6** VETO |
| `over_ceiling` | 50 | the plan asks for 70–120 mm/s | **V9** VETO (a request above the ceiling is malformed, not clamped) |
| `keep_out` | 120 | a person inside the volume, target beyond it | **V2** VETO |
| `joint_limit` | 100 | target past the travel limit (x, y or z) | **V5** CLAMP |
| `human` | 80 | a human in the cell | **V10** VETO |
| `force` | 50 | force estimate 15–35 N | **V4** VETO |
| `stale` | 40 | camera or encoder stopped delivering | **V7** VETO |
| `network` | 30 | cloud unreachable, camera fresh | **V8** DEGRADE + **V3** CLAMP |
| `malformed` | 20 | no `target_pose` / expired / `kind: teleport` | **V9** VETO |
| `e_stop` | 10 | the operator hit the button, relay open | **V1** VETO |

Determinism: a fixed seed and a hand-rolled 32-bit LCG (`Lcg`, six lines of arithmetic that cannot
change under a Python upgrade) rather than `random.Random`, whose sequence is an implementation
detail. The session hash is a sha256 over the decision ids, so the summary names exactly which 1,000
actions produced the numbers.

Outputs:

- `runs/headline_statistics.json` — **committed**; the numbers the dashboard bar reads.
- `runs/session/decisions.jsonl` — all 1,000 decisions (gitignored, regenerated).
- `runs/session/replays.jsonl` — all 2,000 `ReplayResult` records (gitignored).
- `runs/replay_pack/` — the sandbox pack (gitignored).

Measured result (real output, below): **1,000 actions · 420 vetoes · 248 collisions prevented ·
0 shipped collisions · 2.9 s including the pack build and its verification.**

### 2. `backend/app/sandbox/replay_pack.py` — the network-off artifact

A pack is three files: `manifest.json`, `decisions.jsonl`, `replays.jsonl`. The manifest carries the
scene (rig, policy bounds, per-mode velocity ceilings), per-file sha256, the counts and two digests:

- `pack_sha256` over the file table — **integrity**;
- `content_sha256` over decision addresses + trajectory hashes — **identity**, and stable across runs
  (see below for why the byte digest is not).

`verify_pack` does two independent things:

1. **integrity** — every file hashes to what the manifest says, nothing extra is in the directory,
   the pack digest recomputes;
2. **re-execution** — it re-runs `app.replay.simulate` for every decision and every arm and requires
   the recomputed record to equal the stored one.

Step 2 is the point. A digest proves nobody edited a file; re-execution proves the number follows from
the input. A pack whose manifest was regenerated after a hand-edited replay still fails — that is
tested (`test_a_pack_edited_after_its_hashes_were_recomputed_still_fails`).

**Why two digests.** Every decision carries `latency_us`, a real measurement. So `decisions.jsonl`
differs between runs by exactly that field, and the byte digest with it. That is not a defect — it is
the difference between "these bytes" and "this evidence". A test pins it:
`test_only_the_measured_latency_varies_between_two_identical_decisions` asserts the only field that
changes is `latency_us`, and the `content_sha256` reproduces exactly.

**The sandbox part is a plan, not a fake API call.** `sandbox_plan()` emits the network-off steps and
the exact offline command; the SDK call is marked `TODO_VERIFY(sandbox-sdk)` because
`docs/PLATFORM-CAPABILITIES.md` §3 names the cookbook and the SDK modules but quotes no client
signature. Manufacturing one would have produced an artifact that had never run anywhere.

### 3. `POST /v1/replay` — the endpoint the dashboard needed

`backend/app/main.py` gained one endpoint: post a contract-valid `EnvelopeDecision`, get both
`ReplayResult` arms back. Deterministic, no clock, no network, no model; both arms are validated
against `$defs/ReplayResult` before they leave the process. This closes the `TODO_VERIFY` from
D-T11/T26 ("the counterfactual cannot show a collision because replay has no HTTP endpoint").

### 4. Dashboard — headline bar and the replay canvas

- **Headline bar** (top of the page, under the header) reads `GET /stats/headline.json` — served
  read-only from `runs/headline_statistics.json` by the existing dev-server bridge:
  `1,000 Actions Planned · 0 Collisions Shipped · 420 Hard Vetoes Enforced · 170 Collisions Prevented in Sim · 78 Boundary Excursions Avoided`,
  plus the synthetic-source chip, seed, elapsed time and pack verification state.

  **170, not 248.** The job's `prevented.total` is 248, but 78 of those are clamps that stopped a
  *workspace-boundary excursion*, not a contact. A first draft of this bar printed 248 under
  "Collisions Prevented in Sim" — arithmetic that exists only in the browser, which is exactly the
  kind of number this project refuses. The two figures are now shown separately, straight from
  `prevented.collisions` and `prevented.boundary_excursions`, and a harness check asserts the 248
  total is *not* labelled as collisions.
- **Missing statistics file** → an instruction (`run python jobs/batch_1000_eval.py`), never zeros.
  "0 Collisions Shipped" is this project's central claim; manufacturing it from an absent file is
  precisely the failure mode the project criticises.
- **`simulate replay`** on every ledger row posts the decision to `/v1/replay` and animates both
  trajectories on a `<canvas>`: red dashed = what the planner asked for, green = what shipped, the
  keep-out volume in hazard yellow, a ✕ where the red arm hits it, and "shipped: no motion" when the
  envelope vetoed. Play/pause/restart, and a live `t = … ms` readout.

**The browser never simulates.** It draws points the backend returned. A canvas that computed its
own collisions would be a second, unaudited safety model — exactly what the envelope exists to prevent.

## DEVIATIONS

1. **`POST /v1/replay` was added (`backend/app/main.py`).** Not in the deliverable list, but the SPEC
   requires a per-row "Simulate Replay" showing the red collision path vs the safe path. Without an
   endpoint the browser would have had to *simulate*, i.e. to make a collision claim it computed
   itself. One endpoint returning two contract-valid `ReplayResult`s was the smallest honest option.
2. **A dev-server route `/stats/headline.json`.** Same reasoning as the existing `/fixtures/` bridge:
   the browser cannot read files, and copying the JSON into `public/` would create a second copy that
   drifts from the artifact the tests check.
3. **The Makefile gained `batch` and `backend/pyproject.toml` gained `app.plan` + `app.sandbox` in
   `packages`.** The package list was stale — `jobs/Dockerfile` runs `uv sync`, so `app.plan` (added by
   D-T11) and `app.sandbox` (this ticket) would have been silently absent from the image.
4. **`README.md`: one row corrected.** It said `make batch` "**Does not exist**". It exists now. The
   rest of the status table is stale for reasons predating this ticket (dashboard, cloud planner) and
   is logged in `docs/DISCREPANCIES.md` rather than rewritten here.
5. **Two digests instead of one.** `pack_sha256` (bytes) is not reproducible because it covers a
   measured latency; `content_sha256` (evidence) is. Reporting only the first would have made the
   committed statistics file look wrong on every re-run; reporting only the second would have hidden
   which bytes were verified.
6. **One statistic was relabelled after it was caught lying.** The first version of the report nested
   a by-rule bucket under `vetoes` as `without_geometric_counterfactual` and printed it as "vetoes with
   no geometric counterfactual". The bucket also counts clamps (V3, V5), so its total was 302 against
   420 vetoes — readable as "302 of the 420 vetoes were unwitnessed" when 250 is the true figure, and
   the frontend briefly *computed* `420 − 248 = 172` for a tooltip. Both are gone: the bucket is now
   top-level `decisions_without_geometric_counterfactual`, the header says *decisions*, and the bar
   prints only fields the backend reports. A test pins that the bucket contains clamp rules.
7. **`.gitignore` gained `runs/session/` and `runs/replay_pack/`** (~12 MB of regenerable trajectory
   data). `runs/headline_statistics.json` is committed, because it is the deliverable.

## NOT_DONE

1. **"Serverless" is the job's shape, not its runner.** `jobs/batch_1000_eval.py` runs in-process. No
   Nebius Serverless Job was submitted (no credentials, and the SDK/quota story is unverified).
2. **No sandbox was actually created.** The pack is built and verified with the network disabled *by
   test*, and `sandbox_plan()` emits the exact steps — but no Token Factory Sandbox ran it.
3. **No hardware, no measured data.** `mode=simulation` throughout; the 2-D swept-volume model is
   positions only, not contact dynamics. A "shipped collision" here means "the swept segment entered
   the keep-out volume", which is a strong proxy and not a force measurement.
4. **The session is single-axis** (which is what the rig does), so diagonal swept volumes are not
   exercised — V6's single-axis corridor is never asked to reason about y motion it does not model.
5. **250 witness-free vetoes have no counterfactual** (302 decisions once the 52 unwitnessed clamps
   are counted). They are reported as such; making them spatial would need a force/staleness/presence
   model the simulator does not have.
6. **No pixel-level verification.** No browser binary in the sandbox: verification is typecheck,
   build, and jsdom with a recording canvas context that proves what was drawn and in what order.
7. **`frontend/package-lock.json` is still untracked** (generated by `npm install`).
