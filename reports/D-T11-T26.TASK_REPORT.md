## WHAT

### 1. Deterministic gate — the three `xfail`s are gone (`backend/app/gate/gate.py`, `backend/tests/test_gate.py`)

`DeterministicGate.evaluate(rule_id, assertion, evidence_quote, raw_source, *, parameters=None)`
now decides with one table, and every branch is exercised:

| Input | Verdict | `reason_code` |
|---|---|---|
| quote verbatim in the source **and** assertion agrees with the rule's parameters | `PASS` | — |
| quote absent from a source we hold | `FAIL` | `quote_not_in_source` |
| assertion names a parameter the rule does not declare | `FAIL` | `assertion_unknown_parameter` |
| in-scope parameter with the wrong value | `FAIL` | `assertion_contradicts_rule` |
| no quote / blank quote | `UNDETERMINED` | `missing_quote` |
| whitespace, punctuation only, or `< 3` characters | `UNDETERMINED` | `vacuous_quote` |
| `raw_source` missing or blank | `UNDETERMINED` | `source_unavailable` |
| assertion is not a mapping | `UNDETERMINED` | `assertion_unreadable` |
| unknown rule, no parameters loadable | `UNDETERMINED` | `assertion_unreadable` |

Every `UNDETERMINED` carries `routing="escalate_to_human_reviewer"`; `PASS`/`FAIL` carry no
routing key. `_values_agree` refuses `True == 1`. `MIN_QUOTE_CHARS = 3`.

The three former xfails became three positive tests:
`test_gate_must_not_pass_an_assertion_it_never_checked`,
`test_gate_must_not_accept_a_vacuous_quote`,
`test_gate_must_not_accept_evidence_it_cannot_verify`.
`test_result_vocabulary_does_not_match_the_contract` is kept, because it is still true and
still worth knowing.

### 2. V9 refuses structurally invalid proposals (`backend/app/envelope/rules.py`, `core.py`, `__init__.py`)

`test_plan.py` exposed a real defect: a proposal with **no `target_pose`**, an **unknown `kind`**
or **no `ttl_ms`** passed all ten rules and came back `ALLOW`, producing a decision the frozen
contract itself rejects — a shipped action on an untyped payload, and a decision that could not
be written to the ledger.

- `PROPOSAL_KINDS` / `PROPOSAL_SOURCES` moved into `rules.py` (V9 is the rule that enforces them);
  `core.py` imports them instead of keeping a private copy that could drift.
- V9 now checks `kind`, `target_pose.x/y/z` and `ttl_ms` before anything else. Result:
  `VETO` / `V9_PLAN_MALFORMED` with `decision_valid=True` for all three shapes.
- `core._looks_like_action_proposal` was laxer than the contract on `target_pose`; it now
  requires `x`, `y`, `z`. Without this, a contract-rejected payload was copied verbatim into
  `intended_action` and the resulting decision failed `EnvelopeDecision` validation at the ledger.

### 3. Cloud Ultra planner (`backend/app/plan/ultra.py`, `backend/app/plan/__init__.py`)

- `UltraPlanner(completer=…, model=…, ledger_destination=…, now=…)`; `plan(goal, scene) -> Plan`.
- `Completer` is a `Protocol`; `openai_completer()` is the only network-facing code and is lazy
  (`from openai import OpenAI` inside the function), so importing the planner never touches a socket.
- The prompt (`build_messages`, `PROMPT_VERSION = "plan.ultra.v1"`) describes the goal and the
  scene and **never a threshold**; a test asserts no calibration value appears in the rendered prompt.
- `parse_output` handles prose, fenced JSON and `{"proposals": [...]}`; a refusing model returns
  `Plan.abstain_reason` rather than an exception, so the absence of a plan is recordable.
- System-owned fields: `proposal_id`, `plan_id`, `issued_at`, `source="cloud_ultra"` are stamped
  after parsing; model-supplied values are discarded (`_normalise`).
- `route_plan(plan, snapshot, mode=…, destination=…, ruleset=…)` sends **every** proposal, valid
  or not, through `app.envelope.evaluate` + `record_decision`. There is no path from a plan to an
  action that bypasses the envelope.
- Telemetry goes through `app.tf.ledger.record_telemetry` and is disabled by `REFLEX_TELEMETRY=off`.

### 4. Network-outage test (`backend/tests/test_network_outage.py`, 60 tests)

Five assertions, each pinned by tests rather than by a comment:

1. **the cell keeps operating** — 66-case matrix (11 snapshots × 6 proposals) evaluates offline
   with no exception, 10 rules in the trace, contract-valid record; a 30 mm/s request ships at the
   degraded ceiling (24 mm/s) below the normal one (60 mm/s);
2. **degraded is strictly stricter** — every envelope-owned parameter is compared by direction,
   the workspace is a strict subset, and the staleness window *shrinks* (100→50 ms camera,
   50→25 ms encoder) so 60 ms is fresh in normal mode and stale in degraded;
3. **V8 fires and the mode switches** — `DEGRADE`, `parameter_set_used="degraded"`; the debounce
   window does not flap on a 2000 ms blip; a missing `last_cloud_ok_ms_ago` degrades rather than
   assuming the outage is brief; `mode="degraded"` is asserted only against a profile whose
   provenance is `measurement` (the shipped profile is synthetic, so it honestly reports `simulation`);
4. **zero decisions lost** — 600 decisions during a 60 s outage, all durable in the ledger, all
   flagged `buffered_locally`, all back-filled by `reconnect()`; a mixed online/offline session
   keeps its order;
5. **never fail-open** — over the whole matrix, nothing the online path vetoes is allowed offline;
   at least one case exists that tightens (so the matrix is not vacuous); shipped velocity never
   rises; an outage cannot resurrect an expired proposal or repair a malformed one.

### 5. Operator dashboard (`frontend/`)

`src/App.tsx` — three columns, in this order:

| Column | Contents |
|---|---|
| scene / verdict | SVG top-down x–y in millimetres: rail travel, keep-out volume, normal **and** degraded workspace, current pose, intended target (dashed red) and shipped target (solid green); verdict card with outcome, rule, clamp, relay state, `intended v` vs `shipped v`, veto→stop |
| interlocks | V1–V10 in priority order from `GET /v1/envelope/info`, each showing `normal → degraded` parameters and, once a decision is selected, that rule's own `result` and `detail` from `rule_trace` |
| telemetry + ledger | snapshot fields (camera age, end-effector, force, keep-out, relay, network), decision provenance (latency, `determinism_hash`, envelope version), and every decision this page has evaluated with a per-row **counterfactual** control |

Supporting files required for that to render at all: `index.html`, `src/main.tsx`, `src/api.ts`,
`src/types.ts`, `src/styles/app.css`, `tsconfig.json`, `vite.config.ts`, and a `typecheck` script
in `package.json`. `src/tokens.css` is untouched; `app.css` uses `var(--…)` only.

**Simulation is never disguised.** `simulation_badge_required` from the API renders a permanent
header badge ("simulation · synthetic calibration, not hardware") *and* a second badge on the
scene panel, so a cropped screenshot still carries it.

**The counterfactual is honest about its scope.** It draws the decision's own
`intended_action` against its `shipped_action` — real data, no recomputation — and states in the
panel that it makes no collision claim, because the two-arm geometric replay
(`jobs/replay_all.py`) has no HTTP endpoint and its result therefore cannot be fetched. The
alternative would have been to invent a second simulator in the browser.

**Two failure paths are implemented, not decorated:**
- `/v1/envelope/info` unreachable → a full-page gate that says the rule table could not be
  loaded and prints the real error and how to start the API. It renders **no** interlock rows and
  **no** outcome, because a safety screen that invents its limits is worse than a blank one.
- `/fixtures/` unavailable → the select disables and the panel says the corpus is served by the
  dev server; no substitute corpus is generated.

Scenario inputs are the committed corpus, posted unchanged to `POST /v1/envelope/evaluate`:
a dev-server middleware in `vite.config.ts` serves `data/fixtures/snapshots/*.json` read-only at
`/fixtures/` (allow-listed filename pattern; `..%2f` returns 400). Copying fixtures into
`public/` would have created a second corpus that drifts from the one the tests use, and adding a
fixture endpoint would have changed the backend for a UI concern.

## DEVIATIONS

1. **Envelope touched (V9 + `_looks_like_action_proposal`).** The dispatch lists the planner, the
   tests and the dashboard. `test_plan.py` then proved that a proposal with no `target_pose`
   came back `ALLOW` and produced a decision that the frozen contract rejects — a shipped action
   on an untyped payload. Fixing it in the test would have been a lie, so V9 got the structural
   check and `core` was made as strict as the contract it mirrors. No schema change.
2. **Frontend files beyond `App.tsx`.** `App.tsx` alone cannot render: `index.html`,
   `main.tsx`, a `tsconfig`, `api.ts`, `types.ts`, `app.css` and `vite.config.ts` were added.
   `package.json` gained one script (`typecheck`); **no dependency was added** — react, react-dom,
   lucide-react, vite and typescript were already declared.
3. **A dev-server middleware serves fixtures.** Rather than duplicate the corpus into `public/`
   or add a backend endpoint for a UI concern. Consequence: `vite build` output has no fixture
   bridge, and the UI says so instead of inventing one.
4. **Abstention boundary for the gate.** SPEC's parenthetical says "unverifiable evidence
   abstains as the README documents". Implemented reading: `UNDETERMINED` when the gate **cannot
   check** (no/vacuous quote, no source, unreadable assertion, unknown rule); `FAIL` when the gate
   *can* check and the evidence **does not hold** (a quote absent from a source we hold is a
   refutation, not an absence) — protocol §4.2 requires the citation to *resolve*, and
   `ARCHITECTURE.md` says the gate rejects any finding whose citations do not resolve. Recorded in
   `docs/DISCREPANCIES.md`.
5. **Dispatch numbering vs SPEC.** The dispatch calls this ticket D-T26 (dashboard); in `SPEC.md`
   D-T26 is `SAFETY-CASE.md` and the dashboard is D-T28. Followed the dispatch, per the standing
   scope decision, and adopted D-T28's SIMULATION-badge requirement because it is a safety property
   rather than a layout choice. Layout is the dispatch's three columns, not SPEC D-T28's three views.
6. **`mode="degraded"` is not asserted against the shipped profile.** The calibration is
   `synthetic`, so the envelope must report `simulation`; asserting the degraded *badge* would be
   asserting a provenance we do not have. The parameter switch is asserted instead, and the badge is
   proven against a profile relabelled `measurement` in a temp directory.

## NOT_DONE

1. **The network-outage test did not pull a cable.** It proves the software contract (stricter
   parameters, buffer-then-backfill, no fail-open) and nothing about real link behaviour on real
   hardware. SPEC D-T19 assertion 1 says "on real hardware" — this does not satisfy that half.
2. **No live Ultra call.** No API key ⇒ no real completion, no measured cost or latency for the
   planner, and no evidence that the prompt produces valid JSON on the real model. Every planner
   test uses a fake.
3. **No StopButton.** Deliberate (see TODO_VERIFY 5): a stop control with no path to the actuator
   is the single most dangerous thing this UI could contain.
4. **The veto-ledger column is session-scoped**, not the ledger file. There is no HTTP read
   endpoint for `runs/veto-ledger.jsonl`, so the page shows and labels its own history.
5. **No pixel-level verification.** No browser binary exists in this sandbox; verification is
   typecheck + build + jsdom against the live API. Responsive behaviour at 1280 and 1920 is
   implemented with CSS grid and one breakpoint, but was not seen rendered.
6. **The counterfactual shows intent vs shipment, not a collision.** See TODO_VERIFY 4.
7. **`frontend/package-lock.json` is generated and left untracked** (181 entries, produced by
   `npm install`). It is not part of this diff; decide whether the repo wants it committed.
