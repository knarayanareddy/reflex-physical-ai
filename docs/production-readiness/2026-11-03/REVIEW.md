# reflex-physical-ai — independent static review

## Scope and verdict

Revision `1edd4042eb0ec58830978b75176fd6ef1b7e0c66` is a physical-AI safety-envelope **prototype**, with an API and a recorded static replay, not a validated robot safety system. No project code, tests, browser, deployment, network service or hardware was run. Findings concern the inspected source, not a complete audit; production use or autonomy is not established.

## Architecture and product boundary

The API validates the supplied snapshot and proposal, evaluates them and records the result before returning it ([`backend/app/main.py:139–157`](https://github.com/knarayanareddy/reflex-physical-ai/blob/1edd4042eb0ec58830978b75176fd6ef1b7e0c66/backend/app/main.py#L139-L157)). The separate replay route consumes a caller-supplied decision and simulates two arms ([`main.py:160–190`](https://github.com/knarayanareddy/reflex-physical-ai/blob/1edd4042eb0ec58830978b75176fd6ef1b7e0c66/backend/app/main.py#L160-L190)); a standalone CLI also verifies fixtures and replays ledgers. React mounts the dashboard; Pages publishes a recorded bundle, not an API ([`frontend/src/main.tsx:12–19`](https://github.com/knarayanareddy/reflex-physical-ai/blob/1edd4042eb0ec58830978b75176fd6ef1b7e0c66/frontend/src/main.tsx#L12-L19), [`deploy-pages.yml:3–16`](https://github.com/knarayanareddy/reflex-physical-ai/blob/1edd4042eb0ec58830978b75176fd6ef1b7e0c66/.github/workflows/deploy-pages.yml#L3-L16)). FastAPI, React, Python/Node dependencies and GitHub Pages are separate boundaries; the README says the cloud planner is not served and hardware is not wired.

## Findings ledger

- **F01 — high consequence, owner decision:** The README calls the results “1,000 synthetic actions” and says “No hardware ran, no camera existed, no model was called” ([`README.md:14–16`](https://github.com/knarayanareddy/reflex-physical-ai/blob/1edd4042eb0ec58830978b75176fd6ef1b7e0c66/README.md#L14-L16), [`README.md:33–43`](https://github.com/knarayanareddy/reflex-physical-ai/blob/1edd4042eb0ec58830978b75176fd6ef1b7e0c66/README.md#L33-L43)). Its 248 reported adverse end-states comprise 170 geometric contacts and 78 boundary excursions, not 248 physical collisions. Measured rig limits, an independent interlock and a domain safety case require owner and qualified safety-engineer approval before any physical trial.
- **F02 — high if exposed, confirmed static / deployment unverified:** The evaluate handler has no route-level identity check; the standalone server binds `host="0.0.0.0"` ([`main.py:139–157`](https://github.com/knarayanareddy/reflex-physical-ai/blob/1edd4042eb0ec58830978b75176fd6ef1b7e0c66/backend/app/main.py#L139-L157), [`main.py:193–201`](https://github.com/knarayanareddy/reflex-physical-ai/blob/1edd4042eb0ec58830978b75176fd6ef1b7e0c66/backend/app/main.py#L193-L201)). Actual exposure or external authentication was not inspected. Restrict ingress and authenticate/authorize callers before deployment; a response must not itself authorize motion.
- **F03 — medium, confirmed static:** `/health` returns `"status": "ok"` even when `envelope_state` is `unavailable`; the container healthcheck tests only HTTP status ([`main.py:64–86`](https://github.com/knarayanareddy/reflex-physical-ai/blob/1edd4042eb0ec58830978b75176fd6ef1b7e0c66/backend/app/main.py#L64-L86), [`jobs/Dockerfile:43–45`](https://github.com/knarayanareddy/reflex-physical-ai/blob/1edd4042eb0ec58830978b75176fd6ef1b7e0c66/jobs/Dockerfile#L43-L45)). This is legitimate liveness, but insufficient as readiness. Add a distinct readiness contract for validated parameters and storage, without treating it as a safety interlock.
- **F04 — low, confirmed static:** The image uses `FROM python:3.12.7-slim-bookworm`; its own comment says to replace the tag with a digest ([`jobs/Dockerfile:8–16`](https://github.com/knarayanareddy/reflex-physical-ai/blob/1edd4042eb0ec58830978b75176fd6ef1b7e0c66/jobs/Dockerfile#L8-L16)). Mutable tags weaken reproducibility; verify and pin image and workflow dependencies for release.
- **F05 — medium, confirmed static:** The ledger replay skips records without inputs and records from other versions, but exits zero whenever `mismatched == 0`, including when nothing was replayed ([`backend/app/envelope/__main__.py:120–156`](https://github.com/knarayanareddy/reflex-physical-ai/blob/1edd4042eb0ec58830978b75176fd6ef1b7e0c66/backend/app/envelope/__main__.py#L120-L156)). A green exit is not proof of complete verification. Report skipped and stale counts, require explicit completeness policy, and test zero-replayed cases.
- **F06 — medium, confirmed static / rendered usage unverified:** UI strings say “The actuator does not move” and “before it reached the actuator” ([`frontend/src/App.tsx:106–110`](https://github.com/knarayanareddy/reflex-physical-ai/blob/1edd4042eb0ec58830978b75176fd6ef1b7e0c66/frontend/src/App.tsx#L106-L110)), while the README says “the relay itself is not wired” ([`README.md:253–258`](https://github.com/knarayanareddy/reflex-physical-ai/blob/1edd4042eb0ec58830978b75176fd6ef1b7e0c66/README.md#L253-L258)). These are declared strings; their rendered contexts were not inspected. Label outcomes as simulated decisions, not observed actuator behavior.
- **F07 — medium, unverified risk:** Replay validates the supplied decision then uses the current ruleset; the inspected route does not establish ledger membership or matching historical configuration ([`main.py:170–182`](https://github.com/knarayanareddy/reflex-physical-ai/blob/1edd4042eb0ec58830978b75176fd6ef1b7e0c66/backend/app/main.py#L170-L182)). Decide whether it is an arbitrary simulation or authenticated evidence; do not imply provenance until independently verified.

## Five-discipline assessment

**Correctness and physical safety.** The core resolves unmeasured parameters to `"simulation"` and converts rule exceptions into vetoes ([`backend/app/envelope/core.py:119–132`](https://github.com/knarayanareddy/reflex-physical-ai/blob/1edd4042eb0ec58830978b75176fd6ef1b7e0c66/backend/app/envelope/core.py#L119-L132), [`core.py:172–180`](https://github.com/knarayanareddy/reflex-physical-ai/blob/1edd4042eb0ec58830978b75176fd6ef1b7e0c66/backend/app/envelope/core.py#L172-L180)). These are software decisions, not proof of a physical stop. V2 consumes an occupancy flag and evidence; V10 consumes human/intruder flags, not camera images ([`rules.py:163–195`](https://github.com/knarayanareddy/reflex-physical-ai/blob/1edd4042eb0ec58830978b75176fd6ef1b7e0c66/backend/app/envelope/rules.py#L163-L195), [`rules.py:496–511`](https://github.com/knarayanareddy/reflex-physical-ai/blob/1edd4042eb0ec58830978b75176fd6ef1b7e0c66/backend/app/envelope/rules.py#L496-L511)). No detector vocabulary, accuracy or person-recognition capability is established. V6 describes single-axis geometry using advisory poses ([`rules.py:286–321`](https://github.com/knarayanareddy/reflex-physical-ai/blob/1edd4042eb0ec58830978b75176fd6ef1b7e0c66/backend/app/envelope/rules.py#L286-L321)); 2-D replay cannot prove contact dynamics ([`replay.py:14–18`](https://github.com/knarayanareddy/reflex-physical-ai/blob/1edd4042eb0ec58830978b75176fd6ef1b7e0c66/backend/app/replay.py#L14-L18)).

No certification is asserted. Remaining UI, tests, configuration, schemas, calibration contents, storage implementation, hardware and deployment were not inspected. See [remediation plan](REMEDIATION_PLAN.md).
